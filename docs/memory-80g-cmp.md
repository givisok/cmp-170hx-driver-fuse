# CMP-пара: 63 → 79 ГиБ доступной памяти

`nvidia-smi` на всех трёх картах показывал 81920 MiB, но программа (vLLM, torch) на двух
CMP-картах (`10de:20c2`) могла занять только ~63 ГиБ, а на A100-карте — 79. Верхние 16 ГиБ
на CMP-паре не использовались, и vLLM жил так, будто во всех картах по 63.

## Причина

Драйвер на GA100 берёт «usable FB size» не из расчёта конфигурации памяти, а из одного
регистра — `NV_PFB_PRI_MMU_LOCAL_MEMORY_RANGE` (`0x00100ce0`; в патчах cmpunlocker он
называется `LMR`):

```
LOWER_SCALE = биты [3:0]
LOWER_MAG   = биты [9:4]
fbSize = mag << (scale + 20)          // kmemsysReadUsableFbSize_GP102, привязан к GA100
```

От этого значения строятся всё остальное: область прошивки GSP кладётся на вершину
`fbSize`, GSP считает её размером памяти, публичный регион аллокатора заканчивается прямо
под областью прошивки.

| Кто пишет | Значение | Расшифровка | Размер |
|---|---|---|---|
| Прошивка карты на холодной загрузке (mining-конфиг) | `0x288` | mag 40, scale 8 | 40 × 256 MiB = 10 GiB (10 FBP × 1 GiB) |
| Профиль 8gb из upstream cmpunlocker | `0x20b` | mag 32, scale 11 | 32 × 2 GiB = **64 GiB** (8 FBP × 8 GiB) |
| A100 80GB, сток | `0x28b` | mag 40, scale 11 | 40 × 2 GiB = **80 GiB** |

Профиль 8gb рассчитан на непрожжённую карту с 8 FBP. После коммерческого прожига у наших
карт 10 FBP (20 FBPA × 4 GiB), но в регистр всё равно писали 64 GiB. Профиль «80gb»,
сделанный раньше, менял только цифру для `nvidia-smi` (`fb_length` в статической информации
GSP) — поэтому карта «была по 80» на бумаге, а аллокатор отдавал 63.

Правка `late-pma.patch` тут не помогает: она только печатает регион и оставляет его
зарезервированным (`left reserved (backs WPR2)`) — сверху области прошивки ничего нет.

## Фикс: параметр `cmp_lmr`

Параметр модуля `cmp_lmr` (int, default `-1` = профильное значение `0x20b`): если задан,
перед загрузкой GSP в `LOCAL_MEMORY_RANGE` пишется он. Для прожжённых карт — `0x28b`,
ровно как у настоящей A100 80GB.

После этого на CMP-картах происходит то же, что на A100-карте:

```
POST-WRITE ... CFG1=0x02779000 LMR=0x0000028b (devId=0x20c2) stock CFG1=0x02449000 LMR=0x00000288
WPR meta updated fbSize=0x0000001400000000 wprStart=0x00000013f7800000 wprEnd=0x00000013fff00000 ...
normal BooterLoad status=0x0
static-info BEFORE: fb_length=0x1400000000 numRegions=5            ← GSP сам считает 80 GiB
SEC2_DEBUG_HEAP: fbAddrSpace=81920MB ... publicBytes=0x13d30f0000  ← публичный регион 79.35 GiB
```

Хак статической информации становится пустым (GSP и так сообщает 80 GiB), никакой «хирургии
late-pma» не нужно. Включено в `/etc/modprobe.d/cmpunlocker-a100-ss.conf`:

```
options nvidia cmp_a100_ss=1 cmp_lmr=0x28b
```

Откат — убрать `cmp_lmr` (или вернуть `-1`) и перезагрузиться: снова 64 GiB.

## Проверка

Регистр — это только заявленный диапазон; то, что память сверху настоящая, доказывают два
факта: прошивка GSP живёт на вершине 80 GiB и карта грузится, и тест памяти.

`a100/memtest.py` — заполняет почти всю свободную память (`free − 4 GiB`) порциями по 1 GiB
уникальным позиционным паттерном (splitmix64 от индекса), потом перечитывает все порции.
Наложение адресов (две порции на одной физической памяти) или нечитаемый диапазон даёт
несовпадение. Результат 2026-11-27, все три карты:

```
GPU0 [NVIDIA CMP 170HX] SMs=112 total=79.30 GiB  -> 74 GiB, 74 chunks   PASS
GPU1 [NVIDIA CMP 170HX] SMs=106 total=79.30 GiB  -> 74 GiB, 74 chunks   PASS
GPU2 [NVIDIA A100 80GB PCIe] SMs=106 total=79.30 GiB -> 74 GiB, 74 chunks PASS
```

74 GiB > прежних 63.4, значит минимум 10.6 GiB из верхней области участвовало. SM-замер без
изменений (213 / 215 / 215 TFLOPS), холодная загрузка с опцией в modprobe.d — тот же путь,
Xid в журнале нет.

## Как повторить на другой машине

1. Модули, собранные с `a100-ss-param.patch` (там объявлен параметр) и секцией `cmp_lmr`
   в `sec2-postbl-plm-ss-cfg.patch`.
2. Не включая опцию, проверить перезагрузкой модулей:
   `cmp-reload.sh --keep-stopped cmp_lmr=0x28b`, затем в контейнере с CUDA `memtest.py 0`
   на каждой CMP-карте.
3. Если PASS — дописать `cmp_lmr=0x28b` в строку `options nvidia` и перезагрузиться.

Для карт с другим числом FBP значение нужно своё: при scale 11 (`…b`) размер равен mag × 2 ГиБ,
то есть mag = (число FBP × 8 ГиБ) / 2 ГиБ. 8 FBP → 32 = `0x20b`, 10 FBP → 40 = `0x28b`.
